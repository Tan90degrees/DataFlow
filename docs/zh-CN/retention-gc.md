# 保留策略与持久制品垃圾回收

[English](../retention-gc.md) | 简体中文

DataFlow 保持编排元数据持久，同时允许按照显式保留窗口回收对象存储数据和旧事件。

## 安全模型

制品记录保持只追加以便审计。垃圾回收只会在删除前立即重新验证所属尝试/运行状态，然后删除 S3 兼容对象前缀。当非终态运行通过执行单元计划或节点运行输入引用某个已提交制品 URI 时，绝不会删除该制品。

删除是幂等的。如果工作器删除对象后、在 PostgreSQL 记录完成前崩溃，后续轮次可以安全重试同一前缀。PostgreSQL 保存持久扫描游标和每个制品的 GC 目标状态，因此有界轮次无需依赖进程内存即可恢复。

## 策略

收集器读取以下环境变量：

- `DATAFLOW_RETENTION_RUN_SECONDS`：终态运行达到多旧后，才能回收已提交制品或运行事件。默认 7 天。
- `DATAFLOW_RETENTION_EVENT_SECONDS`：事件最短保留时间。默认 30 天。
- `DATAFLOW_RETENTION_STAGING_SECONDS`：尝试进入终态后，其暂存前缀的最短保留时间。默认 1 天。
- `DATAFLOW_RETENTION_ARTIFACT_SECONDS`：已提交制品前缀的最短保留时间。默认 30 天。
- `DATAFLOW_GC_SCAN_BATCH_SIZE`：每轮扫描的最大制品记录数。默认 256。
- `DATAFLOW_GC_WORK_BATCH_SIZE`：每轮处理的最大待处理 GC 目标数。默认 64。

所有保留窗口均可在测试或有意激进清理时设为零。批次大小必须为正数。

## 运行 GC

执行一个有界轮次：

```bash
dataflow-gc
```

检查合格工作但不修改 PostgreSQL 或对象存储：

```bash
dataflow-gc --dry-run --pretty
```

每次只有一个收集器执行工作。PostgreSQL 咨询锁保证重叠调用安全；未获得锁的实例以 `lock_acquired=false` 退出。

## 回收内容

终态尝试超过暂存窗口后，可以删除其尝试专属暂存前缀，包括失败和取消尝试，以及发布后残留的成功暂存数据。已提交前缀要求制品仍为 `COMMITTED`、所属运行已终止且达到保留时间、制品本身达到保留时间，并且没有非终态运行引用该 URI。

足够旧的终态运行事件会在事务本地维护模式中清理。所有其他应用流量仍受普通只追加触发器保护。

本阶段保留流水线运行、执行单元、尝试和制品记录作为持久审计元数据；运行保留窗口是回收关联已提交数据与事件前的下限。

## 可观测性

每轮发出结构化摘要，包含扫描、发现、处理、删除、阻塞、失败数量以及对象/事件删除总数。Prometheus 公开 GC 目标结果、已删除对象总数和已清理事件总数。
