# ADR 0012：持久准入是 DAG 就绪与协调之间的独立层

[English](../../adr/0012-durable-admission-and-fairness.md) | 简体中文

- 状态：已接受
- 日期：2026-09-10

## 背景

依赖调度器目前会把所有满足依赖的 ExecutionUnit 标记为 `READY`，控制器随后可把所有可恢复单元交给 KubeRay 协调器。大量 PipelineRun 同时运行时，控制面工作会失去上限，DataFlow 也没有持久位置执行全局或 ClusterProfile 并发策略。

准入策略必须跨控制器重启保留，并在 HA 领导者故障转移的短暂重叠窗口中保持安全，同时还需要让多个运行确定性向前推进。

## 决策

现有调度器只负责 DAG 依赖语义。在 `READY` 与外部协调之间增加独立 PostgreSQL 支撑的准入控制器。

每个逻辑 ExecutionUnit 有一条当前准入记录，状态为 `WAITING`、`ADMITTED` 或 `RELEASED`。新准入决策通过 PostgreSQL 事务咨询锁串行化，并受可选全局限制、可选 ClusterProfile 限制以及每轮最大新准入数约束。

已准入逻辑单元会跨尝试保留槽位，包括 `RETRY_WAIT`。这样可避免重新获取槽位的竞争，也意味着一个重试单元不会被重复计算为多个活跃尝试。终态/取消工作释放槽位。控制器重启或升级后，已有活跃单元状态足以重建缺失准入记录。

公平性使用单调递增持久准入序号。下一个候选来自最近准入序号最旧的运行，并通过稳定创建时间/ID 打破平局；该运行内部最早排队单元获胜。容量不合格的配置会被跳过，避免队首阻塞其他配置。

## 影响

- 依赖调度保持独立于集群容量策略。
- 即使两个控制器在故障转移期间短暂重叠，已配置准入也不会超过全局/配置限制。
- 重启不会重置公平顺序或丢失槽位所有权。
- 重试退避有意保留容量；这是以部分利用率换取稳定性和简单的一次性逻辑槽位所有权。
- 如果限制降低到已有活跃工作之下，会恢复而不是终止已有工作；在使用量低于上限前停止新准入。
- 每轮准入上限限制新外部工作扇出，同时每轮仍可观察/协调已有准入单元。
