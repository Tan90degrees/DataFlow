# ADR 0013：保留策略与可恢复制品垃圾回收

[English](../../adr/0013-retention-gc.md) | 简体中文

## 状态

已接受

## 背景

DataFlow 有意在 PostgreSQL 中持久化工作流状态、尝试历史和制品发布记录。长期运行的安装还会在对象存储/PostgreSQL 中积累尝试暂存数据、已提交持久制品和事件。清理不能削弱持久恢复能力，也不能删除仍被活跃工作引用的数据。

现有 `artifacts` 表只追加，终态制品记录不可变。S3 发布采用写时复制，并使用运行范围内的尝试专属暂存前缀和稳定已提交前缀。

## 决策

将制品元数据保留为持久审计状态，单独垃圾回收物理对象前缀。GC 维护持久 PostgreSQL 游标以及每个制品的目标记录，其状态为 `PENDING`、`BLOCKED`、`FAILED` 或 `DELETED`。

只有执行尝试进入终态且暂存保留窗口结束后，暂存目标才合格。已提交目标还要求所属运行进入终态、运行/制品保留窗口结束、制品元数据保持 `COMMITTED`，且没有非终态运行引用已提交 URI。

每个目标在删除对象前立即重新验证。对象前缀删除是幂等的，因此物理删除与 PostgreSQL 记录完成之间崩溃时，可以通过安全重复删除恢复。

收集器通过 PostgreSQL 咨询锁串行执行。工作受显式扫描批次和工作批次大小限制。试运行只执行发现/报告，不创建目标、不移动游标、不清理事件，也不操作对象存储。

旧终态运行的旧事件只能在设置 `dataflow.retention_gc=on` 的事务中删除。普通事件变更触发器在该窄维护事务之外保持只追加。

## 影响

- 活跃运行优先于保留压力；被引用的已提交数据会阻塞而不是删除。
- 失败、取消和成功终态尝试留下的暂存数据可以独立于持久元数据回收。
- 重复或中断轮次是安全的，无需对象存储中的分布式租约。
- 制品、尝试、执行单元和流水线运行记录继续可用于审计/调试；本阶段不硬删除这些记录。
- 阻塞目标会在后续轮次重新考虑，活跃引用消失后可变为合格。
- 对象存储生命周期策略仍由运维人员负责，正确性不依赖该策略。
