# DataFlow 路线图

[English](../roadmap.md) | 简体中文

本路线图从 v0.1.0 实现里程碑之后开始。它描述可观察的验收门槛，而不是松散定义的功能清单。只有行为在可行时已自动化，且运维过程已有文档，事项才算完成。

## 发布 v0.1.0

目标：基于仓库现有发布契约，发布首个不可变、可安装版本。

- [ ] 针对目标发布提交运行单元、PostgreSQL 集成、Helm 渲染、KubeRay、HA 和发布验证门禁。
- [ ] 审查生成的 Python、Helm、容器坐标及校验和。
- [ ] 从已验证的 `main` 提交创建不可变标签 `v0.1.0`。
- [ ] 在干净环境中验证 GitHub Release、GHCR 镜像和 OCI Helm Chart。
- [ ] 安装已发布 Chart，并使用已发布运行时镜像提交流水线。

标签是发布边界。验证失败应在新提交中修复；已发布标签不得移动或覆盖。

## 生产验证

目标：证明持久编排语义能够承受常规生产操作。

- [ ] 增加从前一发布版本迁移并滚动升级的自动化测试。
- [ ] 增加回滚测试，证明已有 PipelineRun 保持尝试和 RayJob 标识。
- [ ] 记录并演练 PostgreSQL 备份/恢复和制品存储恢复流程。
- [ ] 增加控制器/API 浸泡测试，覆盖并发运行、重试、取消和 GC 活动。
- [ ] 发布调度器吞吐量和协调延迟基准容量数据。

## 安全基线

目标：提供默认拒绝的部署配置，使运维人员无需自行发现每个加固选项。

- [ ] 增加启用 API 认证、且凭据只来自 Kubernetes Secret 的生产 values 示例。
- [ ] 为 API、控制器、PostgreSQL、对象存储和 RayJob 流量增加可选 Kubernetes NetworkPolicy。
- [ ] 记录 TLS 终止、Bearer 令牌轮换和最小权限运行时身份。
- [ ] 将容器与依赖扫描加入发布阻断检查，并提供有文档的例外流程。

## 可运维性

目标：让值班运维人员能够诊断故障并安全执行日常维护。

- [ ] 为领导权、协调、准入、重试、制品发布和垃圾回收定义告警规则与示例仪表盘。
- [ ] 增加运行卡住、PostgreSQL 不可用、对象存储故障和准入容量耗尽的运行手册。
- [x] 公开控制面构建/版本标识，并在运行诊断中保留运行时镜像坐标，从而将运行组件关联到不可变发布制品。
- [ ] 增加覆盖 Kubernetes、KubeRay、Ray、PostgreSQL 和 S3 兼容存储的兼容性策略。

## 规划规则

工作只有在关联验收测试，或明确说明自动验证为何不可行后，才能进入发布里程碑。新增持久状态需要迁移与回滚考虑；如果改变现有不变量，还需要架构决策记录。
